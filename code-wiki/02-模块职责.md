# 02 - 模块职责

本文介绍仓库布局与每个包的职责。包名统一为 `@deepseek-ai/dsh-<pkg>`，物理位置在 `packages/<group>/<pkg>/`。

## 1. 仓库顶层布局

```
vendor/          vendored 的 Cordis 源码（cordis、cosmokit、schemastery 等）
packages/        所有 @deepseek-ai/dsh-<pkg> 工作区
apps/            cli（dsh 命令入口）、web（前端 Vite 工程）
native/          @deepseek-ai/node-addon-landlock-run（原生沙箱）
python/          Python SDK 与运行时
examples/        可运行的 cordis.yml 叶子示例
docs/            架构、自动生成目录、postmortem、cookbook
scripts/         仓库门禁与生成器
website/         VitePress 文档网站
```

## 3. 核心包详解（core 分组）

`packages/core/` 是产品 API 主干，也是最需要理解的部分。

| 包 | 职责 | ctx 键 |
|---|---|---|
| `core/agent` | `Agent` 接口、实时注册表、创建/恢复工厂委派、`agent/*` 事件 | `ctx.agents` |
| `core/agent-loop` | 具体主循环驱动（唯一包含具体循环逻辑的包） | `ctx.agentLoop` |
| `core/agent-default-model` | 为 agent 提供默认模型路由 | — |
| `core/agent-tool-presentation` | 每个 agent 的工具呈现方式（native/code/both） | — |
| `core/session` | 事件溯源会话：只追加日志、内存存储、派生模型历史 | `ctx.sessions` |
| `core/system-prompt` | 系统提示词组装注册表 | `ctx.systemPrompt` |
| `core/tools` | 工具注册表与执行流水线 | `ctx.tools` |
| `core/scope` | 作用域注册原语（agent 之间隔离注册） | （库） |

## 7. 依赖原则

- **扩展插件依赖 Service Definitions，绝不依赖具体 provider。** `dsh-agent-loop` 是可替换的；UI、hook、工具插件用 `dsh-agent`，而不是 loop 的具体实现。
- **能力 seam 由 Service Definition / Service Provider / Consumer 三角色组成**，只有当角色独立演进时才拆分。
