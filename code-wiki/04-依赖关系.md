# 04 - 依赖关系

本文介绍 `@deepseek-ai/dsh-*` 各包之间的依赖结构、分层原则与依赖方向约束。完整依赖图由 `docs/module-graph.md` 自动生成（`pnpm run gen-module-graph`），下面是它的要点整理。

## 1. 依赖图的来源与规则

- 依赖边由每个包的 `peerDependencies` 推导（这是规范的运行时依赖信号）。
- 边 `a --> b` 表示包 `a` 依赖包 `b`。
- 名称去掉 `@deepseek-ai/dsh-` 前缀。
- 图中有一个跨分组的公共依赖：几乎所有包都依赖 `util/invariants`（不变式伴生包）。

## 2. 分层与依赖方向原则

最重要的两条：

1. **扩展插件依赖 Service Definitions，绝不依赖具体 provider。**
   - `dsh-agent-loop` 是可替换的；UI、hook、工具插件用 `dsh-agent`，而不是 loop 的具体实现。
   - 能力 seam 拆成 Service Definition / Service Provider / Consumer 三角色，正是为了让消费者只面向接口、不绑定实现。

2. **能力包向 core 依赖，core 是产品 API 主干。**
   - 大多数能力包（fs、shell、subprocess、sandbox、web、skill 等）都依赖 `core/*` 与 `llm/llm`。

## 3. 核心依赖关系（分组视角）

### 3.1 util 分组（最底层）

`util/*` 是零依赖工具，几乎所有包都依赖它们的 `invariants`（不变式）。包括：

- `util/atomic-write`、`util/brand`、`util/home-paths`、`util/launch-environment`、`util/native-command`、`util/output-retention`、`util/timeout`、`util/invariants`。

**依赖方向**：`util/*` 被上游所有分组依赖，自身不依赖其它 dsh 包。

### 3.2 core 分组（产品 API 主干）

core 内部依赖关系：

```
scope  --> invariants
session --> brand, llm, scope, typert-protocol
system-prompt --> llm, scope
agent --> llm, scope, session, system-prompt, typert-protocol
tools --> (llm, scope …)
```

- `scope` 是最基础的（只依赖 invariants）。
- `session` 依赖 `llm`（消息词汇）、`scope`、`typert-protocol`、`brand`。
- `agent` 依赖 `session`、`system-prompt`、`scope`、`llm`、`typert-protocol`。
- `agent-loop` 依赖 `agent` 及其它核心接口服务。

### 3.3 llm 分组（模型层）

- `llm/llm` 是抽象服务定义，依赖 `attachment`、`brand`、`invariants`、`timeout`。
- `llm/llm-deepseek`、`llm/llm-pi-ai` 是 provider 适配器，依赖 `llm` + `credentials`、`settings`、`launch-environment`、`timeout`、`anonymous-user-id` 等。
- `llm/llm-retry` 依赖 `agent`、`llm`、`session`（在 `agent/request-error` 上做重试）。

### 3.4 能力分组（fs / shell / subprocess / sandbox / web / skill …）

这些能力包都依赖 `llm`（消息/流词汇）与 `core/*`：

- `fs/fs` 依赖 `brand`、`llm`、`sandbox`。
- `shell/shell` 依赖 `subprocess`（Bash 命令本质是子进程调用）。
- `subprocess/subprocess` 依赖 `util`。
- `sandbox/sandbox` 依赖 `llm`、`session`。
- `web/web` 依赖 `llm`；`web/web-search-*`/`web-fetch-http` 依赖 `web` + `launch-environment`/`timeout`。
- `skill/skill` 依赖 `llm`、`scope`。

### 3.5 子代理与工作流

- `subagent/*` 依赖 `agent`、`session`，通过 `ctx.agents.create()` 创建子代理。
- `workflow/*` 依赖 `skill`、`agent` 等。
- `goal/*` 依赖 `agent`、`session`、`session-projection`、`scope`、`llm`、`typert-protocol`。

### 3.6 数据面（settings / credentials / storage / session-*）

- `settings/settings` 依赖 `brand`；`settings-file` 依赖 `settings` + `atomic-write` + `home-paths`。
- `credentials/credentials` 依赖 `brand`；`credentials-local` 依赖 `credentials` + `atomic-write` + `home-paths` + `launch-environment`。
- `session/session-persistence` 依赖 `session` + `brand` + `timeout`。
- `session/session-projection` 依赖 `session`。
- `session-query/*` 依赖 `session` 等。

### 3.7 界面与协议（host / client / sdk / acp / api）

- `host/*` 系列（API 网关 + HTTP 路由服务器）承载 Web-GUI 的 host 半边。
- `client/*` 系列（浏览器半边）依赖 `host-webserver`（连接）、`client-modules` 等。
- `api/api-gateway` 依赖 `client-connection`、`typert-registry`。
- `sdk/*` 与 `acp/*` 提供进程外协议（JSON-RPC / ACP）。
- `boot/app-boot` 依赖 `home-paths`、`launch-environment`、`system-prompt`。

## 4. 依赖环与健康检查

仓库有多个自动门禁保证依赖健康：

| 脚本 | 作用 |
|---|---|
| `pnpm run gen-module-graph` | 重新生成依赖图（`docs/module-graph.md`） |
| `pnpm run verify-module-graph` | 校验依赖图新鲜度 |
| `pnpm run constraints` | 工作区约束检查（`scripts/check-workspace-constraints.ts`） |
| `pnpm run verify-runtime-closure` | 运行时闭包检查 |
| `pnpm run verify-client-domain-graph` | client 领域图校验 |
| `pnpm run knip` | 未使用依赖/导出检查 |
| `pnpm run publint` | 包发布规范 lint |

## 5. 关键依赖方向速查

| 依赖方 | 被依赖方 |
|---|---|
| 几乎所有包 | `util/invariants` |
| `core/agent` | `core/session`、`core/system-prompt`、`core/scope`、`llm/llm`、`typert-protocol` |
| `core/session` | `llm/llm`、`core/scope`、`brand`、`typert-protocol` |
| `llm/llm-deepseek` | `llm/llm`、`credentials`、`settings` |
| `fs/fs` | `llm/llm`、`sandbox` |
| `shell/shell` | `subprocess` |
| `subagent/*` | `agent`、`session` |
| `session/session-persistence` | `session` |
| `client/*` | `host-webserver`、`client-modules` |
| `api/api-gateway` | `client-connection`、`typert-registry` |
