# 03 - 关键类与函数

本文介绍 `packages/core/` 核心包中最关键的类、接口、函数与事件，帮助理解整个系统的运行机制。核心代码文件位于对应包的 `src/` 目录。

## 1. core/agent —— Agent 服务与注册表

包：`packages/core/agent`，主文件 `src/index.ts`、`src/runtime-types.ts`。

### 1.1 `AgentRegistry`（类，`ctx.agents`）

Agent 服务：跟踪所有存活的 agent，并携带“发起者 Agent”贯穿一条进程内的异步驱动链。

关键方法：

| 方法 | 作用 |
|---|---|
| `create(options)` | 通过注册的工厂创建一个新 agent 及其会话，返回 `AgentHandle` |
| `resume(options)` | 从持久化的会话恢复一个 agent |
| `register(agent)` | 注册一个已构造的 agent，发出 `agent/created` / `agent/disposed` |
| `enter(agent, owner)` / `announce(agent)` | 高级的有序生命周期原语（先构造后发布） |
| `get(id)` | 按 `SessionId` 查找存活 agent |
| `list()` / `roots()` | 列出所有 / 顶层 agent |
| `isOwnedBy(id, owner)` | 判断某个 agent 是否由指定父 agent 创建 |
| `setFactory(factory)` | 注册 agent 创建工厂（由 agent-loop 调用） |
| `withInitiator(agent, op)` / `withoutInitiator(op)` | 显式设定/清除进程内发起者边界 |
| `currentInitiator()` / `requireInitiator()` | 读取继承的发起者 Agent |

### 1.2 `Agent`（接口）

存活 agent 的公共句柄：

| 成员 | 说明 |
|---|---|
| `id` | 与 `session` 共享的唯一标识（`SessionId`） |
| `options` | provider / model / maxTokens |
| `session` | 该 agent 驱动的存活会话（日志是持久化真相源） |
| `inbox` | 待处理工作的投影（`Inbox`） |
| `status` | 生命周期状态：`idle` / `running` |
| `ctx` | agent 作用域上下文（注册内容随 agent 卸载） |
| `cancel(cause, options?)` | 取消当前回合，`keepInbox` 保留待处理工作 |
| `whenIdle()` | 等待整个 agent 达到静默 |
| `runMaintenance(task)` | 在空闲阶段运行一个非回合维护任务 |
| `send(message, target, wakeup)` | 把输入路由到 inbox 边界并选择性唤醒驱动 |
| `followup(message)` | 排队一个普通跟进回合并唤醒 |
| `steer(message)` | 为最近 step 提交转向输入 |
| `inject(message)` | 注入模型可见上下文但不唤醒 |

### 1.3 关键类型

- `CreateAgentOptions` / `ResumeAgentOptions`：创建/恢复选项（sessionId、meta、seed、setup）。
- `AgentSetup`：agent 作用域的“组合式”初始化回调（只组合不驱动）。
- `AgentSetupCommit`：发布前同步校验提交。
- `AgentHandle`：`{ agent, dispose() }`，只有持有者能拆掉该 agent。
- `AgentFactory`：`createAgent(ownerCtx, options)` / `resume(ownerCtx, options)`。
- `AgentStatus`：`'idle' | 'running'`。
- `AgentOptions`：`{ provider?, model?, maxTokens? }`。

### 1.4 `agent/*` 事件（`ctx.events` 扩展点）

| 事件 | 模式 | 作用 |
|---|---|---|
| `agent/created` / `agent/disposed` | emit | 生命周期发布/移除 |
| `agent/status` | emit | 状态翻转（idle ⇄ running） |
| `agent/inbox/inserted` / `claimed` / `discarded` | emit | inbox 变化 |
| `agent/session-start` | emit | 会话生命周期开始 |
| `agent/pre-step` | **waterfall** | 拒绝或改写进入 step 的消息 |
| `agent/request` | **waterfall** | 替换冻结的调用配置 |
| `agent/request-error` | waterflall | 处理失败的模型请求（返回 `{kind:'retry'}`） |
| `agent/turn-stopping` | serial | 回合将要关闭 |
| `agent/error` | emit | step 或 turn 出错 |

## 2. core/agent-loop —— 具体主循环

包：`packages/core/agent-loop`。这是 harness 中**唯一包含具体循环逻辑**的包。

### 2.1 `AgentLoop`（类，`ctx.agentLoop`）

具体的 agent 插件与循环驱动，其内部实现满足 `Agent` 接口，驱动 session/turn/step 生命周期。同时实现 `AgentFactory` 契约并把自己通过 `ctx.agents.setFactory(this)` 注册。

关键方法：

| 方法 | 作用 |
|---|---|
| `create(id, options?, meta?)` | 同步、无 setup 的创建，随调用 fiber 释放 |
| （实现 `AgentFactory`）`createAgent(ownerCtx, options)` | 程序化创建，返回 `AgentHandle` |
| （实现 `AgentFactory`）`resume(ownerCtx, options)` | 从持久化会话恢复 |

### 2.2 配置（schemastery）

```ts
interface Config {
  maxParallelToolCalls?: number   // 默认 10；1 表示串行
  agents: Array<{ id, provider?, model?, maxTokens?, resumeSessionId?, cwd? }>
}
```

配置的 agents 会自动启动。

### 2.3 内部驱动

`ReactLoopAgent`、其 inbox、运行控制是包内部的。驱动运行在 `ctx.agents.withInitiator(agent, ...)` 内。统一 `send()` 原语按（`target` × `wakeup`）路由内容；`followup`/`steer`/`inject` 是其固定预设别名。

## 3. core/session —— 事件溯源会话

包：`packages/core/session`，主文件 `src/index.ts`。

### 3.1 `Session`（类）

事件溯源会话：一个只追加的 `SessionEvent` 日志。普通类（非 Service），通过 `ctx.sessions.create()` 创建存活实例，通过 `Session.create()` 创建分离实例。

关键成员：

| 成员 | 说明 |
|---|---|
| `header` | 冻结的创建元数据（版本、cwd、血缘、seed 边界） |
| `id` | 会话标识（`SessionId`） |
| `events` | 只读的追加日志快照（深冻结） |
| `seq` | 下一个事件的序号（= 日志长度） |
| `surface` | 覆盖日志的有序投影（`SessionSurface`） |
| `append(type, data, opts?)` | 追加一个类型化事件（热路径不阻塞 I/O） |
| `deriveMessages()` | 从日志投影派生 LLM 消息历史（带缓存） |
| `requestHeader()` | 当前生效的请求头（`EpochHeader`） |
| `requestContext()` | 最新路由元数据（`RequestContext`） |
| `firstLiveSeq` | 本进程内第一段追加的 seq |

静态方法：
- `Session.create(id, seed?, header?)`：创建分离会话（validate + snapshot）。
- `Session.fromRestore(id, seed, header)`：恢复分离会话（接管所有权）。

### 3.2 `SessionStore`（类，`ctx.sessions`）

内存会话存储。**注意：持久化不在本包实现**——持久化插件订阅 `session/event`，在 `session/flush` / dispose 时落盘。

| 方法 | 作用 |
|---|---|
| `create(id?, options?)` | 创建存活会话（已进入并发布） |
| `prepare(id?, options?)` | 构造会话但**不**进入存储（与 `enter`+`announce` 配对） |
| `enter(session)` / `announce(session)` | 高级有序生命周期原语 |
| `get(id)` / `list()` | 查找 / 列出存活会话 |
| `fork(source, boundary?, childSessionId?)` | 从存活来源派生一个子会话 |
| `flush(session)` | 派发 `session/flush` 持久化检查点 |

`SessionForkError` 携带拒绝码：`SESSION_NOT_FOUND` / `SESSION_NOT_LIVE` / `SESSION_ALREADY_EXISTS` / `INVALID_BOUNDARY` / `OPEN_TURN`。

### 3.3 `session/*` 事件

| 事件 | 模式 | 作用 |
|---|---|---|
| `session/created` / `session/disposed` | emit | 生命周期发布/移除 |
| `session/event` | emit | 追加事件广播（fire-and-forget） |
| `session/flush` | **parallel** | 持久化检查点（等待所有监听者） |

### 3.4 关键函数

- `adoptSessionEvent(event)` / `snapshotSessionEvent(event)`：校验并深冻结事件。
- `snapshotJsonValue` / `isJsonValue`：无损 JSON 快照。
- `deriveEventMessage(event)`：从单个事件投影消息。
- `foldRequestHeader`、`canonicalHeader`、`headerEquals`：请求头折叠/比较。
- `packChunkRuns` / `decodeStorageRecord`：日志块打包与存储解码。

## 4. core/tools —— 工具注册表与执行流水线

包：`packages/core/tools`，主文件 `src/index.ts`。

### 4.1 `ToolRuntime`（类，`ctx.tools`）

工具注册表 + 执行流水线。执行顺序：

```
tools/pre-execute（可扩展的 allow/deny 门）
  -> 单调的注册守卫（guard）
  -> tools/execute（超时/重试/指标围绕包装）
  -> tools/post-execute（检查/替换结果、附加上下文）
  -> 定义拥有的 finalizeContent 边界
  -> observe-only 的 tools/result 通知
```

关键方法：

| 方法 | 作用 |
|---|---|
| `register(definition)` | 注册一个受信任的工具定义（带强制 `output` 声明） |
| `presentAs(mode)` | 选择本 agent 的模型可见呈现（native/code/both） |
| `restrict(filter)` | 应用 agent 作用域的 allow/deny 掩码 |
| `get(name, scope?)` | 按某作用域解析工具定义 |
| `schemas(scope?)` | 该作用域能看到的所有工具的 schema |
| `guard(guard)` | 注册单调的同步执行守卫 |
| `execute(exec)` | 运行完整策略/分发/结果流水线 |
| `executionMode(exec)` | 返回 `parallel` 或 `exclusive` |

工具注册辅助：`defineTool()`（带类型化参数 schema）、`validateArgs`、`valueSchemaSpecToJsonSchema` 等。

### 4.2 关键类型

| 类型 | 说明 |
|---|---|
| `ToolDefinition` | `ToolSchema` + 强制 `output` + `execute(args, exec)` + 可选回调 |
| `ToolExecution` | 只读流水线视图：`{ token, callId, name, arguments, signal, agent?, parent? }` |
| `ToolRunContext` | 传给工具体的执行，扩展 `deferContext(context)` |
| `ToolExecutionResult` | 区分成功的执行局部结果（成功=`isError:false`，失败=`isError:true`） |
| `ToolExecutionToken` | 注册表分配的内部品牌 Symbol（仅相等相关，不跨边界） |
| `PreToolDecision` | `{kind:'allow'} \| {kind:'deny',reason} \| {kind:'ask',reason?}` |
| `PostToolDecision` | 接受（可替换 content/value）+ 阻塞（转为失败） |
| `ToolGuard` | `(execution) => string \| undefined`，返回拒绝原因 |
| `ToolCallView` / `ToolResultView` | 工具拥有的 UI 渲染意图（card 标签） |

### 4.3 `tools/*` 事件

`tools/pre-execute`、`tools/execute`、`tools/post-execute` 是三个可变换的 waterfall，`tools/result` 是 observe-only。注意 `tools/result` 是实时事件，同名 `tool/result` 才是 agent loop 之后追加的持久会话事件。

### 4.4 Code Mode

`ctx.tools` 的 `mode` 配置选择 `native` / `code` / `both`。`code` 模式暴露保留的 `run_code` 传输和一个按当前作用域生成的 SDK；模型只能直接调用 `run_code`，其它工具通过 SDK 绑定调用。

## 5. core/system-prompt —— 系统提示词组装

包：`packages/core/system-prompt`，主文件 `src/index.ts`。

### 5.1 `SystemPrompt`（类，`ctx.systemPrompt`）

组装注册表。插件贡献有序片段、工具 schema、命名变量；loop 每 step 组装一次并渲染为完整 model prompt。

关键方法：

| 方法 | 作用 |
|---|---|
| `section(section)` | 贡献一个片段（`{name, order, text, complete?}`） |
| `context(context)` | 贡献有序动态上下文 |
| `suppressRuntimeContext()` | 抑制所有动态上下文贡献 |
| `tools(provider)` | 贡献工具 schema（每次组装时求值） |
| `variable(name, provider)` | 贡献一个 prompt 变量（`{{name}}`） |
| `assemble(context?)` | 为某个调用者组装 prompt |

`renderPrompt(assembly)`：插值 `{{variable}}`，丢弃空片段，空行连接。未知/无值/畸形引用会**显式抛错**（fail loud）。

### 5.2 关键类型

- `PromptSection`：`{name, order, text, complete?}`，按 `order` 升序拼接。
- `PromptAssembly`：`{sections, tools, variables}`。
- `AssembleContext`：一次 `assemble()` 是为“谁”服务（`scope?`、`signal?`，agent 扩展 `agent?`）。

## 6. core/scope —— 作用域原语

包：`packages/core/scope`，主文件 `src/index.ts`。

### 6.1 关键函数

| 函数 | 作用 |
|---|---|
| `createScope(ctx, key, options?)` | 创建一个带标签的 Cordis 上下文，其 fiber 拥有所有注册 |
| `scopeOf(ctx)` | 读取上下文携带的作用域标签 |
| `scopeTarget(base, key)` | 为作用域过滤事件构建不透明分发 `thisArg` |
| `bindScopeParent(key, parent)` / `scopeParentOf` / `scopeChainOf` | 作用域父链关系 |

### 6.2 关键类型

- `Scoped<T>`：编译期不透明载体品牌（作用域过滤事件要求它作 `this`）。
- `Scope`：`{ ctx, dispose(), rawDispose }`。
- `ScopeLayer`：一个注册表完整全局或精确作用域贡献的聚合契约。
- `ScopedLayers<L>`：持有 eager 全局层 + lazy 精确作用域层。
- `NamedEntries<V>` / `AnonymousEntries<V>`：有序存储。

## 7. 其它核心包

- **core/agent-default-model**：为 agent 提供默认模型路由。
- **core/agent-tool-presentation**：每个 agent 的工具呈现方式（native/code/both）。
