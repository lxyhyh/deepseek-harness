# 01 - 架构总览

本文介绍 DeepSeek Harness 的整体架构思想、核心运行机制与数据流。

## 1. 项目定位

DeepSeek Harness（`dsh`）是 DeepSeek AI 开发的开源 **Agent 运行框架（agent harness）**。它把“一个 AI 智能体如何运行”这件事做成一个可配置、可扩展、可持续记录的系统。当前处于 **developer preview** 阶段，可能包含破坏性变更。

运行一个 `dsh` 实例，最终会得到一个能接收用户消息、调用各种工具（文件系统、Shell、网页搜索、子进程等）、与大模型多轮交互，并把整个过程持久化记录下来的智能体。

## 2. 核心架构思想

### 2.1 一切皆插件（Everything is a plugin）

这是整个项目最根本的设计原则。**没有特权内核**，没有“打补丁”式的核心。

- 模型适配器（LLM adapter）是插件。
- 工具注册表（tool registry）是插件。
- 会话日志（session log）是插件。
- Agent 主循环（agent loop）本身也是插件。

因此，任何一部分都可以通过**组合/替换插件**来改变，而不是修改核心代码。扩展 `dsh` 的方式就是“在旁边挂上一个插件”。

### 2.2 基于 Cordis 框架

Cordis 是 `dsh` 底层的插件框架，提供四个核心能力：

| 能力 | 说明 |
|---|---|
| **Context（上下文）** | 插件共享的运行时上下文，通过 `ctx` 访问 |
| **Service（服务）** | 可注入、可替换的服务，如 `ctx.tools`、`ctx.sessions` |
| **Events（类型化事件）** | 插件间通信的扩展点，如 `agent/pre-step`、`tools/execute` |
| **Effect（可逆副作用）** | 插件注册的东西在插件卸载时自动回滚、清理 |

Cordis 被 **vendor 到本仓库**（不是通过 npm 安装），见 [vendor/](../vendor/README.md)，这样框架层完全由项目自己掌控（可审计、可打补丁、可固定版本）。

### 2.3 Profile 与 Bundle（组合模型）

一个运行的 `dsh` 是**启动时按层级组合出来的插件树**：

- **Profile（配置档案）**：一个命名的组合，存于 Harness 主目录（`$DSH_HOME/profiles/<name>`）。它列出自己要叠加的 bundles、安装的插件，以及用户自己的 `cordis.patch.yml`。
- **Bundle（分发单元）**：Cordis 配置行 + 对应代码的分发格式，插入的内容可以被上层继续打补丁。

层级应用顺序（从底到顶）：
1. profile 列出顺序中的每个 bundle
2. profile 自己的 `cordis.patch.yml`
3. 主目录级 `$DSH_HOME/cordis.patch.yml`
4. 任何 `--patch` 覆盖层

三个内置 bundle：
- `dsh-base`：每个 profile 的第一层（模型适配器、工具、持久化、沙箱与审批策略、设置、凭据、遥测）。
- `dsh-web-app`：加上浏览器应用（Web UI）。
- `dsh-headless`：加上一次性运行器，无服务器。

## 3. 核心包（Core）

`packages/core/` 是产品 API 主干，包含 6 个核心包：

| 包 | 职责 | ctx 键 |
|---|---|---|
| `core/session` | 只追加的 `SessionEvent` 日志与内存存储 | `ctx.sessions` |
| `core/system-prompt` | 系统提示词与工具 schema 的组装 | `ctx.systemPrompt` |
| `core/tools` | 作用域化工具注册表与受保护的执行流水线 | `ctx.tools` |
| `core/agent` | `Agent` 接口、实时注册表、`agent/*` 事件 | `ctx.agents` |
| `core/agent-loop` | 实现该接口的默认驱动（主循环） | `ctx.agentLoop` |
| `core/scope` | 每个 agent 的作用域注册原语 | 库，无键 |

## 4. 事件（Events）——扩展点

事件是扩展点。选择正确的领域是大多数改动最先要做的决定。

| 事件域 | 特征 | 用途 |
|---|---|---|
| **Session events** | 持久化事实，追加到日志并广播 | 需跨重启存活的事实 |
| **Agent events（`agent/*`）** | 携带实时 `Agent`：inbox、step、status、request 等 | 观察或拦截进行中的工作 |
| **Capability events（`fs/*`、`tools/*`、`telemetry/*`）** | 为能力接缝挂载策略与适配器 | 不导入主循环即可扩展能力 |

## 5. 运行数据流（Turn / Step）

一次交互的抽象单位：

- **Step（步骤）**：一次模型请求 + 它调用的工具。
- **Turn（回合）**：零个或多个 step，从首个输入被认领开始，到不再“欠债”时关闭。

典型流程（简化）：

```text
turn/start
  认领下一个 step 的输入外加一条排队消息
  组装 prompt 片段 + 工具 schema
  -> agent/pre-step（可拒绝或改写进入的消息）
     step/start
     追加进入的消息为 user/message
     从日志推导模型历史
     agent/request -> llm/stream -> assistant/chunk* -> assistant/message
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     （若工具还欠一个请求，或新输入到达）-> 认领 -> 下一个 step
  -> agent/turn-stopping
turn/end
```

`turn/*`、`step/*`、`user/message`、`assistant/*`、`tool/*` 是**持久化**会话事件；其余是**实时**扩展点。其中 `agent/pre-step`、`agent/request`、`llm/stream`、三个 `tools/*` 事件是 **waterfall（瀑布）**，监听者必须调用 `next()` 才能把控制交给下一个；`agent/turn-stopping` 是串行事件，没有 `next()`。

## 6. 会话日志（Session log）

会话日志是模型看到上下文的**源头**。`deriveMessages()` 从日志投影出模型历史，原始的 `assistant/chunk` 事件保留重放与 UI 保真度。

**黄金法则：模型可见即被记录（Model-visible ⟺ logged）。** 任何进入模型请求的内容都必须能从日志重建；运行时不变式负责断言这一点。因此，新增一个“模型可见输入”就需要新增一个 session event。

## 7. 能力接缝（Capability Seam）

**能力接缝（seam）** 是一个可替换的能力，包含三种角色：

- **Service Definition（服务定义）**：声明接口。
- **Service Provider（服务提供者）**：实现接口。
- **Consumer（消费者）**：使用接口，通常是模型可见的工具。

三者缺一不可；只做一个角色不算一个接缝。这是“换一个 provider 就改变整个产品”的原因——例如文件系统与子进程 provider 共享同一执行世界，指向远程沙箱就能同时移动 Bash、PTY、LSP。

## 8. 新功能的落点（Where new behavior goes）

下表给出“想做什么 → 挂到哪个扩展点”的快速索引：

| 目标 | 机制 |
|---|---|
| 加一个模型 provider | 在 `ctx.llm` 注册适配器 |
| 加一个模型可见能力 | 在 `ctx.tools` 注册；其 schema 加入 prompt 组装 |
| 加 Shell 执行 | 注册 `ctx.shell` 后端 |
| 加持久化终端 | 注册 `ctx.terminals` 后端 + `dsh-tool-terminal` |
| 加后台任务 | 在 `ctx.jobs` 注册；`job_*` 工具收集/停止 |
| 加文件系统访问或策略 | 注册 `ctx.fs` provider 或监听 `fs/*` |
| 拦截请求/工具/回合 | 使用 `agent/*` 或 `tools/*` 事件 |
| 加模型可见上下文 | 调用 `agent.inject()` |
| 加持久化会话状态 | 扩展 `SessionEventMap`；从日志渲染与重放 |
| 派生一个实时会话 | `ctx.sessions.fork(source, boundary?, childSessionId?)` |
